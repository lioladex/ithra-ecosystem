## 0. Voice charter
กำหนดโดยเจ้าของโปรเจกต์ในการสัมภาษณ์สไตล์วันที่ 2026-08-30 เมื่อกฎข้อถัดๆ ไปขัดกับหมวดนี้ ให้ยึดหมวดนี้เป็นหลักเสมอ เพราะกฎด้านล่างเป็นเทคนิค ส่วนนี้คือเป้าหมายที่เทคนิคเหล่านั้นรับใช้

**ระยะ: อยู่ในตัว.** ผู้อ่านรู้เท่าที่ Confluence รู้ และรู้สึกในจุดที่ Confluence รู้สึก ห้ามถอยออกไปเป็นมุมมองที่ตัวละครไม่มี ห้ามมีผู้บรรยายแบบสำรวจที่อธิบายระบบนิเวศข้ามไหล่ตัวละคร

**เนื้อสัมผัส: ยาวและไหลลื่นเป็นค่าเริ่มต้น.** ประโยคพื้นฐานยาว มีอนุประโยคต่อกันไปเรื่อยๆ พาผู้อ่านไปกับกระแส ประโยคสั้นห้วนไม่ใช่สไตล์หลัก แต่เป็นข้อยกเว้นที่ใช้ตอนถึงจุดพีค ถ้าทั้งฉากอ่านเป็นบรรทัดสั้นหมด แปลว่าใช้พลังไปหมดแล้วแต่ไม่มีอะไรกระทบใจ

**รายละเอียด: เฉพาะสิ่งที่ร่างกายรับรู้ได้เท่านั้น.** กายวิภาคและนิเวศวิทยาเข้ามาผ่านความรู้สึก แรงกด กลิ่น อุณหภูมิ แรงต้าน สิ่งที่ Confluence รับรู้/เห็นไม่ได้ ให้อยู่ในฐานข้อมูลที่ผู้อ่านไปค้นเองได้

**โทน: หม่น เหงา.** ไม่ใช่การสังเกตแบบเย็นชา ไม่ใช่ความสิ้นหวัง เป็นโทนของสิ่งที่อยู่ตัวเดียวในที่กว้างใหญ่ เรียนรู้สิ่งที่ไม่มีใครจะถามมันเลย ความอบอุ่นมีอยู่ในเรื่อง แต่เสมอในฐานะสิ่งที่สังเกตเห็นจากภายนอกเสมอ

**sysnote: เสียงของบางอย่างที่กำลังเฝ้ามอง.** บรรทัด `[LOG]` ไม่ใช่เครื่องจักรบรรยายตัวเอง แต่อ่านเหมือนบันทึกที่เก็บโดยผู้สังเกตที่ติดตามชีวิตนี้มา จดสิ่งที่เปลี่ยนไป ด้วยศัพท์แบบคนวัดค่า ไม่เคยพูดกับ Confluence และ Confluence ไม่เคยได้ยินมันเลย ตัวเลขแม่นยำตรงนี้ แต่ในเนื้อเรื่องระยะทาง/ช่วงเวลาเดียวกันยังคลุมเครือ วัดเป็นความยาวลำตัว วัน และสายตามองไปได้ไกลแค่ไหน

**การเน้น: 2-3 บรรทัด glow-danger ต่อบท.** เป็นจุดที่ตัวละครเปลี่ยน ไม่ใช่จุดที่งานเขียนดังขึ้น

**การจบ: คำถามที่ยังตอบไม่ได้.** บทจบด้วยการยื่นสิ่งที่เรื่องยังตอบไม่ได้ให้ผู้อ่าน แล้วฉาก close sequence พาสิ่งนั้นออกไปเป็น core memory

## 1. ความรู้สึกมาก่อนความเข้าใจ
Confluence รู้สึกถึงสิ่งหนึ่งก่อนจะเรียกชื่อหรือเข้าใจมันได้ ห้ามให้การบรรยายยื่น label ที่มันยังไม่มีสิทธิ์รู้
- แย่: `รู้จักคำว่า เจ็บ` (สื่อว่ารู้คำนี้อยู่แล้ว)
- ดี: `รู้สึกว่า เจ็บ` / บรรยายทางกายภาพดิบๆ แล้วให้การ "เข้าใจ" มาทีหลังเป็นจังหวะแยกที่มองเห็นได้ (ดู `shock-collapse`: ความเจ็บได้ชื่อตอนนั้นพอดี มาร์คด้วย `<em class="glow-danger">`)
- ใช้กับความรู้สึกใหม่ทุกครั้ง (ความหิว, กลิ่นเป็นทิศทาง, การบิน, ความเจ็บ) — บรรยายข้อมูลทางสัมผัสดิบก่อน แล้วให้ "อ๋อ" เป็นจังหวะที่มองเห็นแยกออกมาต่างหาก

## 2. ห้ามใช้ชื่อสปีชีส์จริงในเนื้อเรื่อง
Confluence ไม่รู้จักชื่อจริง ในบทสนทนา/การบรรยาย (ไม่ใช่ tag, sysnote, comment, หรือ UI label — จุดเหล่านั้นใช้ชื่อจริงได้อิสระ) สิ่งมีชีวิตได้รับชื่อเล่นเชิงบรรยายจากมุมมองไร้เดียงสาของ Confluence:
- Karvos → เจ้าตัวสี่ขา
- Skyther → เจ้าเงาปีกกว้าง / เงาปีกกว้าง
- Vashli → เจ้าตาโต
- ร่างเดิมของ Confluence เอง → ร่างเดิม / ร่างสี่ขาที่เคยสวมอยู่ (ห้ามเรียก "Luvenn" ตรงๆ ใน `paragraphs`)

เมื่อเพิ่มสิ่งมีชีวิตใหม่เข้าเรื่อง ให้คิดชื่อเล่นจากลักษณะภาพ/พฤติกรรมเด่นจุดเดียว ไม่ใช่จากอนุกรมวิธาน

## 3. รายละเอียดคำบรรยายปรับตามระยะ
รายละเอียดกายวิภาคที่ย่อหน้าให้ต้องสอดคล้องกับว่า Confluence อยู่ใกล้/มองนานแค่ไหน:
- ไกล/เห็นแวบเดียว → เห็นแค่เงาดำ ลักษณะเด่นคลุมเครือ 1-2 อย่าง (เช่น เห็น Skyther ครั้งแรก: แค่ "เส้นขอบปีกกว้าง" ไม่มีจำนวนตา ไม่มีรูปทรงปาก)
- ใกล้/มองต่อเนื่องนาน → รายละเอียดสัมผัสเต็ม (จำนวนตา โครงสร้างปาก เนื้อสัมผัส ลายเรืองแสง) — รายละเอียดนี้ต้อง *เพิ่มขึ้น* จริงระหว่างการเจอสิ่งมีชีวิตเดียวกันซ้ำ ห้ามซ้ำคำบรรยายเดิมสองครั้ง
- การไล่ระดับนี้คือวิธีที่ข้อความสอน skill แบบ "สังเกต" ได้ความหลากหลาย — action สังเกตซ้ำแต่ละครั้งต้องโชว์แง่มุม/เทคนิคที่ *ต่างกัน* ไม่ใช่เห็นภาพเดิมซ้ำแค่เปลี่ยนคำ

## 4. ผูกสิ่งเหนือธรรมชาติเข้ากับกายภาพจริง
การแปลงร่างของ Confluence (การจำลองเซลล์ใหม่เป็นแบบจำลองของต้นแบบที่เจอ ไม่ใช่การสิงร่าง) ต้องอ่านเป็นกระบวนการทางกายภาพที่สัมผัสได้เสมอ — กระดูก ผิวหนัง กล้ามเนื้อจัดเรียงตัวใหม่ — ห้ามเป็นการแปลงร่างแบบแฟนตาซีทั่วไป ("เวทมนตร์," "แสง," เอฟเฟกต์แสงทั่วไปในฐานะ *สาเหตุ*) ยึดทุกขั้นตอนกับความรู้สึกทางร่างกาย ตรงกับกฎข้อ 1

## 5. ตัดข้ามช่วงที่ทนไม่ไหว
เมื่อบางอย่างจะหนักเกินกว่าจะเล่าทีละจังหวะ (การสลบไป, วินาทีที่ปลิดชีวิต) ให้ตัดย่อหน้าตรงขอบแล้วเล่าต่อหลังจากนั้น แทนที่จะเล่าผ่านมันไปทั้งหมด จังหวะว่างเปล่า (ประโยคสั้นโดดๆ เช่น `ความมืดกลืนทุกอย่างไปหมด`) ทำหน้าที่ time-skip แทน — ไม่ต้องอธิบายช่องว่างนั้นเกินจำเป็น

## 6. จังหวะตรงกับโมเมนต์
- จังหวะแอ็กชัน/ช็อก: ประโยคสั้นห้วน หยุดกระชับ ปัจจุบันกาลทันที
- จังหวะสงบ/ครุ่นคิด: ประโยคยาวไหลลื่น อนุประโยคเยอะขึ้น จังหวะช้าลง
- เก็บ `<em class="glow-danger">` ไว้สำหรับ 1-2 คำ/วลีต่อฉากที่ต้องกระแทกใจที่สุด (สัญชาตญาณตะโกน, ความรู้สึกที่เพิ่งได้ชื่อ) — ใช้เกินจะทำให้เอฟเฟกต์เรียบเฉย

## 7. เอฟเฟกต์เฉพาะกิจต้องมีคอมเมนต์อธิบายเหตุผล
เหตุการณ์เชิงเนื้อเรื่องใดๆ ที่มีผลข้างเคียงเชิงกลไกที่ไม่ตรงกับ `recoveryAction`/`teachesSkill` มาตรฐานของสิ่งมีชีวิต (เช่น การฟื้น AP เล็กน้อยจากการสลบที่ `shock-collapse`) ต้องมาพร้อม code comment สั้นๆ อธิบายว่า *ทำไม* ถึงไม่ตรง canon และทำไมฉากนั้นเฉพาะเจาะจงถึงสมเหตุสมผล — กันไม่ให้ editor ในอนาคต "แก้" มันให้ตรง canon โดยไม่ตั้งใจ

## 8. เนื้อหาแยกทางต้องรู้สึกถูกแต่งขึ้นมาจริง ไม่ใช่แปะต่อ
เมื่อ `paragraphs`/`text` เป็นฟังก์ชันที่แยกทางตามตัวเลือกก่อนหน้า (เช่น เตะหรือไม่เตะที่ T+8/T+9) ทั้งสองทางต้องอ่านเป็นร้อยแก้วที่ตั้งใจเท่ากัน — ห้ามให้ทางไหนรู้สึกเป็นแค่ตอนสั้นๆ แปะต่อจากทางที่ "จริง" กว่า

## 9. บรรทัดปิดบท-ประมวลความคิด (`reflections` ใน JOURNEY_CHAPTERS)
ทุกบทจบด้วยลำดับประมวลความคิด: บรรทัดมุมมองบุคคลที่หนึ่งสั้นๆ ที่ลอยเข้ามาแล้วจางหายไป ตามด้วยบัญชีได้-เสีย กฎเฉพาะของบรรทัดเหล่านี้:
- นี่คือจุดเดียวที่ Confluence พูด "ฉัน" — เป็นการประมวลผลภายใน ไม่ใช่การบรรยายฉาก ห้ามให้สรรพนามนี้หลุดเข้าไปใน `paragraphs` ของ step
- 1 บรรทัดต่อ 1 บีตที่สำคัญจริง เรียงตามลำดับที่เกิดขึ้นในบทนั้น ไม่มีบรรทัดสำหรับสิ่งที่ผู้อ่านไม่เห็นบนหน้า
- `kind: "gain"` = สิ่งที่ได้มา (ความรู้สึก, ความสามารถ, ความเข้าใจ) `kind: "loss"` = สิ่งที่ถูกพรากไป (ร่างกาย, ฝูง, ความเชื่อที่กลายเป็นเท็จ) ความเชื่อก็นับ — การเสียความเชื่อผิดๆ คือบรรทัด loss ไม่ใช่ gain
- เก็บประโยคไว้ที่การตั้งชื่อสิ่งที่ได้/เสีย ไม่ใช่ว่ารู้สึกยังไงตอนนั้น (ฉากทำหน้าที่ความรู้สึกไปแล้ว) "ฉันได้รู้จักความเจ็บปวด" ไม่ใช่ "ฉันเจ็บจนแทบขาดใจ"
- เล็งให้มีทั้งสองแบบผสมกันแล้วจบที่ต้นทุนจริงของบท บทที่มีแต่ gain ล้วนอ่านเป็นเช็คลิสต์
- บทใหม่ทุกบทต้องมี array `reflections` — หน้าจอปิดบทเล่นให้อัตโนมัติและสร้างบัญชีจากมัน
- Confluence ยังไม่มีคำศัพท์เชิงศีลธรรม/นามธรรมในช่วงนี้ ไม่มีความรู้สึกผิด ไม่มีความโหดร้าย ไม่มี "ความเชื่อ" ที่จะเสียได้ การฆ่าคือ `ล่า` ไม่ใช่ `ฆ่า` สมมติฐานที่หายไปคือคำตอบที่หายไป ขอบเขตที่หายไป หรือนิสัยที่หายไป — ไม่ใช่ความเชื่อที่หายไป
- มันไม่เคยเสียร่างสี่ขาไป — ร่างถูกจำลองใหม่เป็นร่างใหม่ ไม่ใช่ถูกพรากจากมัน สิ่งที่เสียต้องเป็นสิ่งที่หยุดมีอยู่จริงๆ (ฝูง, การกินแสงแบบไม่ต้องออกแรง, การเดินที่ไม่ต้องคิด)

## 10. รูปทรงของบท (กลั่นจาก Chapter 2 ที่เจ้าของโปรเจกต์อนุมัติเป็นจังหวะเป้าหมาย)
บทหนึ่งเดินเป็น 3 องก์ และขอบเขตขององก์ควรมองเห็นได้ในแท็กของ step:
1. **เรียนรู้ร่างกาย (slice of life).** พฤติกรรมเดิมที่ติดตัวมา 2 อย่างล้มเหลวก่อนจะสำเร็จอะไรเลย — ท่วงท่าเก่าที่ไม่มีอวัยวะรองรับแล้ว, อาหารเก่าที่ลำไส้นี้ย่อยไม่ได้ ปิดองก์ด้วยสิ่งเดียวที่มีแค่ร่างนี้เท่านั้นทำได้ ทำเพราะอยากรู้ ไม่ใช่เพื่อรอด
2. **สังเกตแทนที่จะตอบโต้.** ตัวเอกติดตามสิ่งที่เคยหนีมันมาก่อน จากระยะที่ปลอดภัยจากภัยคุกคาม การเฝ้ามอง ไม่ใช่การต่อสู้ คือบีตหลัก องก์ 2 จบด้วยการเผชิญหน้าครั้งเดียวที่จบก่อนจะมีตัวเลือกใดๆ เกิดขึ้น
3. **ผลลัพธ์และการจากไป.** องก์สั้นองก์เดียวที่แปลงการเผชิญหน้าให้กลายเป็นคำถาม และชี้ไปยังจุดหมายถัดไป

## 11. การสังเกตต้องเพิ่มพูน ไม่ใช่ซ้ำเดิม
action สังเกตซ้ำกับเป้าหมายเดียวกันแต่ละครั้งต้องเผยชั้นข้อมูลที่ต่างกัน — องค์ประกอบและบทบาท, แล้วตรรกะของเส้นทาง, แล้วจังหวะการโจมตี — และครั้งสุดท้ายควรตีความสิ่งที่ครั้งก่อนๆ หมายถึงใหม่ (ฝูงที่เมินตัวล่อคือความรู้ที่เก่ากว่าตัวใดตัวหนึ่งในฝูง) ถ้า action สังเกตใหม่สลับที่กับอันเก่าได้โดยไม่เสียอะไร แปลว่ามันไม่ใช่ action ใหม่จริง

## 12. จบด้วยคำถามที่แหลมขึ้น
บทหนึ่งจบด้วยการแทนที่ความสับสนเก่าด้วยคำถามที่ก่อรูปดีกว่าเดิม ไม่ใช่ด้วยคำตอบ Chapter 1 จบด้วยความเข้าใจนักล่า Chapter 2 จบด้วยการตอบไม่ได้ว่าเสียงที่สั่งให้ยืนหยัดคือเสียงของอะไร คำตอบเป็นของบทถัดๆ ไปที่จะได้รับมันเอง

## 13. ความหนาแน่นสำคัญกว่าความยาว
Chapter 1 มี 17 step กับ 17 action; Chapter 2 มี 9 step กับ 22 action บทที่สองอ่านดีกว่า เลือก step น้อยกว่า ยาวกว่า มี action เสริม 2-3 ตัวต่อ step แทนสายโซ่ step บางๆ ยาวๆ ทุก step ที่มี 3 action ที่ตัด AP ต้องมีแหล่ง AP อยู่ใน step นั้นหรือ step ก่อนหน้าทันที ไม่งั้น action จะเข้าไม่ถึง — เช็คตรงนี้ก่อนเขียน ไม่ใช่หลังเขียน

## 14. Checklist ความแข็งทื่อ (รอบที่ Chapter 3 เดิมต้องการ)
โหลด general skill ก่อนรอบแก้ไข: `writing-principles` บอกว่าช่องรางวัลผู้อ่านช่องไหนที่ย่อหน้าแบนราบทำพัง และ `creative-writing-craft` (resources/prose-writing.md) มีเรื่อง psychic distance, จังหวะ, และ interiority ปัญหาที่เกิดซ้ำในโปรเจกต์นี้โดยเฉพาะ:

- **ประโยคอธิบายหลังบีต.** "เงาปีกคลุมลงบนพื้นตรงนั้นพอดี" ตามด้วย "จบเร็วมาก เร็วกว่าที่เคยเป็นมาทุกครั้ง เพราะคราวนี้รู้อยู่แล้วว่าต้องทำอะไรตรงไหน" ประโยคที่สองบอกสิ่งที่ประโยคแรกทำไปแล้ว ตัดทิ้ง ถ้าย่อหน้าจบด้วยการสรุปย่อหน้าตัวเอง สรุปนั้นคือปัญหา
- **รายการแทนที่จะเป็นภาพเดียว.** อนุประโยคขนาน "รู้ว่าตัวไหน…" สามอันลงเบากว่าภาพสัตว์ตัวเดียวที่แผงข้างซ้ายเปิดไม่สุด เลือกรายละเอียดจุดเดียวที่แบกรายละเอียดที่เหลือได้
- **เรียกชื่อหมวดก่อนความรู้สึก.** "ความหิวไม่ได้มาแบบค่อยเป็นค่อยไป" ประกาศสิ่งที่ร่างกายกำลังจะแสดง เริ่มด้วยขาหลังที่สั่น ผู้อ่านประกอบ "ความหิว" เอง นี่คือกฎข้อ 1 ที่ระดับประโยค
- **ระบุความรู้สึกด้วยการปฏิเสธ.** "ไม่ใช่ความหิว ไม่ใช่ความกลัว ไม่ใช่ความอุ่น" ก็ยังเป็นการติดป้าย แทนที่ด้วยสิ่งที่ร่างกายทำ: มันอยู่บนกิ่งทั้งวันและไม่เคยไปกินเลย
- **จังหวะแบนราบตรงจุดพีค.** จุดพีคทางอารมณ์และช่วงเปลี่ยนผ่านธรรมดามาในประโยคความยาวปานกลางแบบเดียวกัน จุดพีคต้องการประโยคสั้นและหยุดกระชับ การครุ่นคิดต้องการบรรทัดยาว ถ้าฉากอ่านสม่ำเสมอตั้งแต่ต้นจนจบ ไม่มีบีตไหนในนั้นกระทบใจเลย

แก้ด้วยการตัดก่อนเสมอ ความแข็งทื่อส่วนใหญ่ในโปรเจกต์นี้คืออนุประโยคเกินมาหนึ่งอัน ไม่ใช่อนุประโยคที่ขาดหายไป

## 15. คำติดปาก (รัน `node scripts/check-prose.js`)
สคริปต์นับคำติดปากที่โปรเจกต์นี้ใช้ซ้ำจริง แล้วพิมพ์ฉากที่กระจุกตัวหนักที่สุด ไม่เคยบล็อก commit — คำเหล่านี้ไม่ผิดในตัวเอง ปัญหาคือความถี่ วิธีแก้:

| คำ | ทำอะไรกับมัน |
|---|---|
| ราวกับ | ตัดทิ้งแล้วบรรยายสิ่งที่เห็นตรงๆ หรือหาภาพเปรียบที่เจาะจงกว่า |
| เลยแม้แต่นิดเดียว · เลยสักนิด · ทั้งนั้น | ตัดทั้งวลี ความหมายไม่เปลี่ยน |
| เลยสักครั้ง · แม้แต่ครั้งเดียว | เก็บไว้เฉพาะจุดที่ "ไม่เคยเลย" คือใจความ ที่เหลือตัด |
| จริงๆ | ตัด ถ้าประโยคต้องยืนยันตัวเองแปลว่ายังไม่หนักแน่นพอ |
| อย่างชัดเจน · อย่างสิ้นเชิง · อย่างแท้จริง · อย่างประหลาด | ตัด แล้วบอกว่าเห็นอะไรแทน |

**Em dashes** อยู่ต่ำกว่าประมาณ 1 ต่อ 8 ท่อนต่อบท (สคริปต์พิมพ์เพดานให้) เลือกใช้จุด, จุลภาค, หรือแยกประโยคแทน เก็บไว้เฉพาะจุดที่การขัดจังหวะคือใจความ

Checklist นี้มาจากการรีวิวสกิล `stop-slop` (github.com/hardikpandya/stop-slop) กฎเรื่อง filler, formulaic-structure, concreteness, และ trust-the-reader ใช้ได้ตรงกัน ส่วนกฎ "ทุกประโยคต้องมีประธานที่เป็นคน", "เรียกผู้อ่านว่า you", และ "ลบประโยคที่ยกไปพูดได้" ใช้ไม่ได้ — โปรเจกต์นี้ตัดประธานโดยตั้งใจ ไม่มีสรรพนามที่พูดกับผู้อ่านนอกจากฉากตื่นรู้กับบรรทัดปิดบท และต้องการมีบรรทัดที่ยกไปพูดได้พอดี 1 บรรทัดต่อฉากที่มาร์คด้วย `glow-danger`

## 16. เรียกความสัมพันธ์ระหว่างอนุประโยค
การตัด dash ทิ้งจะเหลืออนุประโยคสองอันวางติดกันโดยไม่บอกตรรกะระหว่างมัน ภาษาไทยพกตรรกะนั้นไว้ในคำ ให้ใส่กลับเข้าไปแทนที่จะปล่อยให้ผู้อ่านเดา:

| ความสัมพันธ์ | คำที่ใช้ | ตัวอย่างในเรื่อง |
|---|---|---|
| พลิกความคาดหมาย ประธานเดิมแต่ผลตรงข้าม | **กลับ** (วางหน้ากริยา) | "ทุกอย่างที่สะสมมาก่อนหน้านี้ยังอยู่ในหัวครบ **กลับ**ใช้ไม่ได้สักอย่างเดียว" |
| ขัดแย้งระหว่างสองข้อความ | **แต่** | "เหมือนที่เคยทำมานับพันปี **แต่**ตอนนี้ไม่มีขาสี่ข้างแบบเดิมให้ทิ้งน้ำหนักลง" |
| สะสมเพิ่ม | **และ** | "ต่างจากกลิ่นดินชื้นที่คุ้นเคยมาตลอด **และ**เป็นครั้งแรกที่กลิ่นมีความหมายมากกว่าแค่กลิ่น" |
| เหตุนำไปสู่ผล | **จึง** | "พุ่งเข้าใส่ก่อนจะพร้อมจริง **จึง**พลาดเป้าไปเฉียดๆ" |
| เข้มข้นจนเกิดผล | **จน** | "กางออกเป็นจังหวะที่แม่นยำมาก **จน**เห็นชัดกว่าตอนไหนๆ" |

`กลับ` แข็งแรงที่สุดในกลุ่มนี้และเฉพาะเจาะจงกับเรื่องนี้ที่สุด เพราะทั้งโปรเจกต์วิ่งอยู่บนร่างกายและสัญชาตญาณที่ทำตรงข้ามกับสถานการณ์ที่เรียกร้อง เก็บไว้ใช้กับกรณีนั้น: ประธานเดียวกัน ผลลัพธ์พลิกกลับ ห้ามซ้อนกับ `แต่` เว้นแต่ทั้งสองฝั่งต้องการเน้นจริงๆ

เว้นอนุประโยคสองอันไว้เปล่าๆ ได้เฉพาะตอนที่อันที่สองเป็นการเรียกชื่อซ้ำ (apposition) หรือตอนที่ความเงียบระหว่างมันคือใจความ ถ้าเรียกความสัมพันธ์ไม่ได้ ประโยคนั้นน่าจะมีอนุประโยคเกินมาหนึ่งอัน ซึ่งคือกฎข้อ 14

## 17. บรรทัดปิดบทคือ core memory ไม่ใช่สรุปเนื้อเรื่อง
ฉากปิดคือสิ่งที่ Confluence เก็บไว้จากบทหนึ่ง ไม่ใช่รายการสิ่งที่เกิดขึ้นในบทนั้น เก็บไว้ที่ **ห้าหรือหกบรรทัด** บรรทัดหนึ่งจะมีที่ยืนได้ก็ต่อเมื่อบทนั้นจะมีความหมายต่างไปถ้าไม่มีมัน: การรับรู้ถึงการมีอยู่ครั้งแรก, ความเจ็บครั้งแรก, การล่าครั้งแรก, ความทรงจำที่เรียงลำดับครั้งแรก, สิ่งที่ถูกพรากไป ที่เหลือควรอยู่ในฉากที่มันอยู่แล้ว

กฎการเรียงลำดับที่ตามมาจากตรงนี้:
- บรรทัดสุดท้ายคือบรรทัดที่ผู้อ่านควรพกติดตัวเข้าไปในบทถัดไป จบด้วยต้นทุนหรือคำถามเปิด ไม่ใช่ gain
- ทุกบทที่แยกทางจบด้วยบรรทัดร่วมชุดเดียวกันบวก 2 บรรทัดที่ต่างกันตามร่างที่ได้มา เพื่อให้ผู้อ่านเห็นเส้นทางของตัวเองถูกเอ่ยถึง
- บัญชีได้-เสียในการ์ดปิดบทลิสต์บรรทัดเหล่านี้เป๊ะๆ ถ้าบีตหนึ่งควรค่าแก่แถวในบัญชี มันก็ควรค่าแก่บรรทัดลอย และถ้าไม่ควร มันก็ไม่ควรอยู่ในทั้งสองที่

## 18. การเคลื่อนไหวในฉากปิด
ไม่มี motion-graphics skill ติดตั้งอยู่ (registry ไม่มี ตัวที่มีบน GitHub เล็งไป Remotion หรือ GSAP video pipeline ไม่ใช่ in-page HTML) กฎเหล่านี้มาจากการเอา anti-pattern ของ ui-ux-pro-max — animation หนักมือ และ timing ที่ไม่สนใจ component/ผู้ใช้ — มาใช้กับฉากนี้:

- **จับเวลาแต่ละบรรทัดตามความยาวของมันเอง.** `REFLECT_BASE + chars × REFLECT_PER_CHAR` เพดานที่ `REFLECT_MAX_LINE` บรรทัดสี่คำไม่ต้องการเวลาหกวินาทีเท่ากับอนุประโยครอง
- **ซ้อนทับตามสัดส่วน ไม่ใช่ช่องว่างตายตัว.** บรรทัดถัดไปเริ่มที่ `REFLECT_OVERLAP` ของบรรทัดปัจจุบัน จังหวะจึงคงสัดส่วนไว้ไม่ว่าบรรทัดจะพูดอะไร
- **เพดานบีบเฉพาะช่องว่าง ไม่ใช่เวลาอ่าน.** เมื่อบทหนึ่งเกิน `REFLECT_TOTAL_CAP` ให้บีบ delay เหลือเวลาบนจอของแต่ละบรรทัดไว้เท่าที่มันต้องการ
- **ขยับนิดหน่อย เบลอนิดหน่อย.** ลอยขึ้น ค้าง ล่องลอย พร้อม scale เล็กน้อย อะไรที่คมกว่านี้จะอ่านเป็นเอฟเฟกต์แทนที่จะเป็นความคิดที่ผุดขึ้นมา
- **เคารพ `prefers-reduced-motion`.** ซ่อนลำดับทั้งหมดแล้วโชว์การ์ดปิดพร้อมบัญชีทันที ไม่มีใครเสียเนื้อหา เสียแค่ animation
- **เว้นปุ่มข้ามไว้เสมอ.** ยี่สิบวินาทีคือเวลานานสำหรับผู้อ่านที่อ่านไปแล้ว

## Workflow เมื่อถูกขอให้ขัดเกลาเนื้อเรื่องเดิม
1. อ่าน step เป้าหมายแบบเต็มบริบท (step รอบข้างด้วย — โทนต้องไหลต่อกัน)
2. เช็คแต่ละย่อหน้ากับกฎข้อ 1-6 ข้างบน
3. เช็คความสม่ำเสมอชื่อเล่น (กฎข้อ 2) — grep หาชื่อสิ่งมีชีวิตจริงที่หลุดเข้าไปใน `paragraphs`/action `text` (tag, sysnote, comment, และ UI string อย่าง `continueLabel` ได้รับการยกเว้น)
4. เสนอการแก้ที่เล็กที่สุดที่แก้จุดผิดกฎ — ห้ามเขียนย่อหน้าที่ทำถูกอยู่แล้วซ้ำเพื่อ "ปรับปรุง" เพิ่ม เนื้อเรื่องของโปรเจกต์นี้ผ่านรอบรีวิวมาหลายรอบแล้ว การแก้เกินจำเป็นทำให้ความสม่ำเสมอของน้ำเสียงเสียไป
